| Mode | URL | What you need |
|---|---|---|
| Hosted | [test.solana.vanna.finance](https://test.solana.vanna.finance) | A browser and a wallet pointed at `https://rpc-devnet.solana.vanna.finance` |
| Local | `http://localhost:3000` | Surfpool, the contracts repo and the app repo |

Both run on a **Surfpool mainnet fork**: real mainnet programs and accounts (USDC, xStocks, Kamino, Jupiter, Phoenix…) cloned on demand, with Vanna's programs deployed on top. Nothing touches real Mainnet funds.

Developer details: [Developer Setup](/developers/setup).

## Hosted (fastest)

1. Add the fork RPC to your wallet ([how](/guides/connect-wallet#add-the-vanna-rpc-to-your-wallet)).
2. Open [test.solana.vanna.finance](https://test.solana.vanna.finance) and connect.
3. **Faucet → Fund All**.

## Local

Two repos, side by side:

```text
vanna-credit-layer/     # Anchor programs: vanna_credit_layer (core), vanna_oracle, vanna_validator
vanna-credit-backend/   # Next.js app: UI and server routes
```

### 1. Build the programs and start a fork

From `vanna-credit-layer`:

```bash
anchor build
mkdir -p /tmp/vanna-fork && cd /tmp/vanna-fork
surfpool start --network mainnet --no-tui --no-deploy
```

### 2. Deploy and bootstrap

In a second terminal, from `vanna-credit-layer/scripts`:

```bash
npm install
bash bootstrap-fork.sh
```

This writes the three programs onto the fork at their declared IDs (no deploy keypair needed) and registers assets, reserves and integrations. The wallet that runs it (`~/.config/solana/id.json` by default, or `ANCHOR_WALLET`) becomes the protocol admin.

### 3. Run the app

From `vanna-credit-backend`:

```bash
npm install
cp .env.example .env.local   # then edit it
npm run dev
```

Point your wallet's custom RPC at `http://127.0.0.1:8899` and open [http://localhost:3000](http://localhost:3000).

### Minimum `.env.local`

```dotenv
NEXT_PUBLIC_SOLANA_RPC_URL=http://127.0.0.1:8899
NEXT_PUBLIC_SOLANA_WS_URL=ws://127.0.0.1:8900
FORK_RPC_URL=http://127.0.0.1:8899
NEXT_PUBLIC_VANNA_PROGRAM_ID=H37YVBG3eGtz89ofd7iDLc2PJgn12778392XeU2QJcGC
ACCESS_CODE=<pick-a-code>
```

`.env.example` lists every other setting (Jupiter, Titan and Alchemy keys, Copilot, Analytics, Predict). Leave a key empty to turn that feature off.

<Warning>
Never put a secret in a `NEXT_PUBLIC_*` variable: those are shipped to the browser. API keys, RPC URLs with keys, and keypairs belong in server-only variables, and `.env.local` is git-ignored.
</Warning>

## Program tests

```bash
cd vanna-credit-layer
cargo test --manifest-path programs/vanna_credit_layer/Cargo.toml
```

## Check the hosted RPC

```bash
curl -sS https://rpc-devnet.solana.vanna.finance \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"getVersion"}'
```

A healthy node returns its `surfnet-version` and `solana-core` version.

## Common problems

| Symptom | Fix |
|---|---|
| Wallet shows real balances / previews fail | The wallet isn't on the fork RPC |
| "Blockhash not found" | The wallet and the app are on different RPCs |
| Empty balances | Use the Faucet on **this** fork |
| Every page asks for an access code | Set `ACCESS_CODE` in `.env.local` and enter it once |
